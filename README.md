# IMDG Code 中文规则检索（Demo）

把《国际海运危险货物规则》中文版 PDF 自动拆成可检索的结构化数据，做成一个**离线可用的网页检索工具**。

---

## 1. 结论速览

| 问题 | 结论 |
|---|---|
| 22 版（41—22）→ 24 版（42—24）差别大吗？ | **改动面看起来很大（7 个部分、27 章都动了），但真正日常要用的“危险货物一览表”只有 2.5% 的 UN 条目被改动**，且多数只是加一个特殊规定号、改一个积载类，属于“小修”；实质性大改集中在钠离子电池、锂电池、车辆/设备、灭火剂分散装置等少数条目 |
| 按 24 版做会有问题吗？ | **按 24 版做是对的**：42—24 已于 **2026-01-01 生效**（文件里明确写了），41—22 自 2025-12-31 起不再适用。真正的风险是“拿 24 版内容当 22 版用”，而这个问题可以用“改动清单打标 + 双版本视图”解决 |
| 能不能一份数据同时支持两个版本？ | **能**。IMDG 每两年是“整本替换”，改动清单本身就是逐条“在第 X 栏，将 A 替换为 B”的指令，**反推即可得到 22 版**；没被清单点到的字段，两版完全相同 |

## 4. 差异量化（41—22 → 42—24）

- **覆盖面**：第 1—7 部分全部有改动，涉及 27 个章。
- **一览表**：79 处改动、涉及 **60 个 UN 条目**；另有 **11 条整条重写**（UN 0514、3551–3560）。合计占全部 UN 条目的 **2.5%**。
- **改动动作**：替换 62 处、增加 58 处、删除 17 处、插入 10 处。
- **改哪一栏最多**：特殊规定（第 6 栏）36 次 > 积载与操作（第 16a 栏）12 次 > 特性与注意事项（第 17 栏）8 次 > 名称/包装类 各 4 次。
- **条款改动最多**：第 3.2 章（83）、第 3.3 章（33）、第 6.2 章（9）、第 4.1 章（8）、第 5.5 章（7）。
- **最“实”的改动**（会直接影响操作）：
  - **钠离子电池**整章级新增：UN 3551、3552 重写，新增 UN 3558（钠离子电池驱动的车辆），SP 188/230/296/310 等加入“或钠离子”
  - **锂电池**：UN 3480/3481 的特性与注意事项重写，SP 376/377/384/387/388 系列调整
  - **车辆/设备**：UN 3556、3557、3558 条目更新
  - **灭火剂分散装置**：UN 0514（1.4S）与 UN 3559（第 9 类）整条重写
  - **5.5.4**“运输中在用或计划使用的含有危险货物的装置”新增要求（2028-01-01 起适用）
  - 名称/参数类实质改动：UN 1010（40%→20%）、UN 1835（名称）、UN 3423（第 8 类→6.1，包装类变化）
- **典型“小修”**：`UN 1006：第6栏中，增加“406”`、`UN 0331：第14栏中，删除“TP1”`。

> 这正是“按 24 版做”的风险画像：**只有约 2.5% 的条目会不一致，但其中一部分是“看起来同名、数值却不同”的实质差异**（如 UN 3423 的类别/包装类），这类差异靠肉眼比对很难发现，用工具打标才是解法。

## 5. 制作方案

### 阶段 0（本次 Demo，已完成）
PDF → 结构化数据 → 倒排索引 → 静态网页检索。零依赖、可离线、双击即用。

### 阶段 1（可上线，1–2 周）
1. **校对层**：字段级与英文原版比对 + 抽样人工复核（重点：跨页行、空单元格、代码断行）。
2. **同义词/别名表**：中文品名、英文品名、UN 号、俗称、旧译名互通（搜“汽油”能到 UN 1203）。
3. **结构化跳转**：点卡片里的 `SP310`、`P001`、`IBC02`、`T4`、`SGG2` 直达定义（Demo 已实现基本版）。
4. **双版本视图**：以 24 版为底，把改动清单当作“补丁”回放，生成 22 版视图，并标注“该栏两版不同”。
5. **增量更新机制**：每两年一个新修正案，只需解析新清单 + 重新打标，不必重做全量。

### 阶段 2（产品化）
- 后端检索（SQLite FTS5 / Meilisearch / Elasticsearch），支持权限、统计、收藏、导出。
- 扩展语料：本 PDF **不含《补充本》**（EmS 指南、MFAG、报告程序、INF 规则），需要另行准备文档。
- 合规工具化：隔离矩阵计算器、限量/可免除量计算器、包装与单证检查表、国别差异（主管当局等效规定）提示。
- 质量体系：黄金样本回归测试（固定 UN/条款的期望输出）、版本 diff 自动化。

## 6. 数据管线原理

1. **取文字**：PyMuPDF 逐页取单词及其坐标；剔除页眉页脚（`MSC 108/20/Add.2`、`附件8，第X页`、`DANKA\CHINESE\...`）。
2. **定位表格**：危险货物一览表是**横向双栏排版**（左栏第 1–11 列、右栏第 12–18 列），栏间有 22 条竖线 → 用竖线坐标定义 21 个列区间（其中 1 个是两栏之间的空列）。
3. **识别行**：用**第 1 列和第 18 列（都是 UN 号）的 4 位数字作为行锚点**，再用该栏的**横线**（`get_drawings()` 取）作为行的上下边界。同一横线带里出现多个锚点，就是被合并/多包装类的行。
4. **拼单元格**：把词按坐标归到（行 × 列）；单元格内换行时，**若上一行文字顶到了列的右边**则判定为“断字”，直接拼接而不加空格 —— 这样才能还原 `IBC02`、`500mL`、`P001 LP01` 这类值。
5. **切条款**：正文页按“条款号 / 代码 / SP 号”作为切分点，继承页眉里的部分与章上下文。
6. **建索引**：中文按**二元组**切词（无空格语言不用分词器也能召回），英文与数字按单词；生成含词频的倒排索引，用 varint + base64 压缩（2.2 MB）。
7. **打分**：前端 BM25 打分；命中后再做一次**原句包含校验**并加权，抑制二元组的误召回。

## 7. 目录结构

```
scripts/    解析与构建脚本（可重跑）
  parse_dgl_final.py      一览表解析（最终版）
  build_clauses.py        条款/特殊规定/代码切分
  build_index_entries.py  书末索引解析
  build_changelog.py      42—24 改动清单解析
  build_search_index.py   倒排索引 + 文档集
  gen_web_data.py         生成网页数据
  test_search.js, test_render.js   Node 自测
data/       中间数据（json/jsonl）与抽样截图
web/        网页（index.html + app.js + style.css + data/*.js）
```

## 8. 如何使用

方式一：直接双击 `web/index.html`（数据用 `<script>` 加载，`file://` 也能跑）。
方式二：跑本地服务（推荐，性能更好）：

```bat
start-demo.cmd
```

检索示例：

- `1203` / `UN 3082` → 一览表条目（多包装类分行显示）
- `7.1.5` / `4.1.4.1` → 规则原文
- `SP310` / `P001` / `IBC02` / `T4` → 代码定义
- `锂离子电池` / `积载类E` / `SGG2` / `海洋污染物` → 全文检索
- 顶部“版本差异 42-24”页签 → 完整改动清单

## 9. 已知边界与验收清单

- **中文本的非权威风险**：两份中文文件在个别译名上不一致 —— 例如 UN 3560 的中文名，正文与索引都是“四甲基氢氧化铵含量**不低于** 25%”，而改动清单写的是“**不超过** 25%”。上线前须与英文原版逐字核对。
- 表格按几何规则解析，**跨页行、极少数空单元格**仍需人工抽检。
- 第 4.2.5.2.6 的 T 代码（罐柜导则）在原文里是表格，暂只做到“能搜到所在条款”。
- EmS / MFAG 属《补充本》，不在本 PDF 内。
- 中文分词用的是二元组，正式版建议加专业词典与同义词。

**验收建议**：随机抽 30 个 UN 号 + 20 条条款 + 10 个代码，与 PDF 原文逐字段比对，字段准确率目标 ≥ 99.5%。
